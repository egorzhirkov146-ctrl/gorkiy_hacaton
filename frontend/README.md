# Пульс — голосовой ассистент для задач и встреч

Frontend-компонент хакатона GorkyCode. React + Vite, адаптивная страница ассистента, текстовый чат, запись аудио, списки событий и воспроизведение ответа.

## Обновлённый интерфейс

- Светлая рабочая область, зелёные акценты и тёмная боковая панель.
- Стартовый экран с тремя примерами запросов; кнопка подставляет текст для проверки перед отправкой.
- Многострочный ввод: Enter отправляет, Shift + Enter переносит строку.
- История не прокручивается вниз, когда вы читаете старые сообщения; есть кнопка возврата к новым.
- Очистка с подтверждением, отменой по Escape и сохранением событий. Сбрасывается также незавершённое уточнение в демо.
- Запрос доступа к микрофону имеет отдельное состояние; повторный запуск блокируется.
- Неотправленный текст возвращается в редактор при ошибке.
- События сгруппированы по датам; есть обновление и сброс пустой выборки.
- На телефоне навигация находится внизу; списки событий открываются отдельным экраном.
- Системные шрифты без загрузки Google Fonts, поддержка reduced-motion и видимый фокус клавиатуры.

## Быстрый старт

Требуется **Node.js 20.19+ или 22.12+** и npm.

```bash
npm ci
cp .env.example .env        # Windows PowerShell: Copy-Item .env.example .env
npm run dev
```

Перейдите по адресу, который выведет Vite (как правило, http://localhost:5173).

**По умолчанию включён демо-режим** (`VITE_DEMO_MODE=true`). Он загружает реальные 1000 строк из переданного CSV, поддерживает текстовые сценарии создания, просмотра и поиска, умеет спрашивать недостающую дату/время. Созданные пользователем записи и переписка хранятся в localStorage браузера. Исходная база CSV не изменяется. В демо используется *упрощённый локальный разбор текста*, а не LLM. Произвольный естественный язык обеспечивается backend.

В демо-режиме голос распознаётся **опционально** через встроенный Web Speech API, только в поддерживаемых браузерах; если API не работает, текстовый ввод доступен всегда. При подключённом backend запись гарантированно передаётся в `/stt` (при доступном микрофоне/поддержке формата), а ответ в `/tts`.

## Подключение реального backend

Откройте `.env`, установите:

```dotenv
VITE_DEMO_MODE=false
VITE_BACKEND_URL=http://localhost:8000
```

Перезапустите Vite. В dev он проксирует `/api/*` на backend, убирая префикс `/api`, поэтому backend должен реализовать следующие маршруты. Этот контракт предлагается frontend-командой; **сам PDF ТЗ конкретный API не определяет**. Его нужно согласовать с backend-разработчиками.

### 1. `POST /stt` — распознавание речи

Запрос: `multipart/form-data`, поле `file` (Blob с фактическим MIME: `audio/webm`, `audio/mp4` либо `audio/ogg` по поддержке браузера). **Не задавать Content-Type вручную**: браузер добавляет boundary.

Ответ JSON:

```json
{ "text": "Добавь встречу завтра в 15:00" }
```

Допускается алиас `transcript` вместо `text`.

### 2. `POST /chat` — обработка естественного языка

Запрос JSON:

```json
{
  "message": "Что у меня завтра?",
  "session_id": "uuid-сессии"
}
```

Ответ JSON:

```json
{
  "reply": "Завтра запланирована встреча с командой в 15:00.",
  "session_id": "uuid-сессии",
  "events": [
    { "id": "42", "type": "meeting", "title": "Встреча с командой", "date": "2026-10-22", "time": "15:00", "status": "pending" }
  ]
}
```

`events` необязателен; используется для ответов со списком/поиском, но боковая панель всё равно обновляет `/events` после каждого успешного запроса.

Сервер **сам** выполняет создание, чтение, поиск и при необходимости задаёт уточняющие вопросы через `reply`, сохраняя контекст по `session_id`.

### 3. `GET /events` — все сохранённые задачи/встречи

Ответ: массив событий либо `{ "events": [...] }`. Для больших реальных баз рекомендуется добавить серверную пагинацию или фильтры; текущий frontend получает полный список, поскольку исходный CSV содержит только 1000 записей.

Объект события:

```json
{
  "id": "103",
  "type": "task",
  "title": "Подготовить отчёт",
  "date": "2026-10-22",
  "time": "11:00",
  "status": "pending"
}
```

Поддерживаются `type`: `task`, `meeting`, `reminder`, `event`. Можно не передавать `time` и `status`. Значение `event` используется для исторических строк CSV, где тип неизвестен. Поддерживаются статусы `pending` и `completed`; произвольные значения показываются текстом.

### 4. `POST /tts` — синтез речи

Запрос JSON: `{ "text": "Готово, встреча создана" }`.

Ответ — **сырые аудиобайты**, например `audio/mpeg`, с заголовком `Content-Type: audio/mpeg`. Не JSON/base64. Запись воспроизводится через `HTMLAudioElement`.

При необходимости backend может изменить API; адаптер запросов находится в **`src/services/api.js`**, а остальные компоненты не потребуется переписывать.

### Публикация проекта

Скомпилируйте `npm run build`. Опубликуйте содержимое `dist/` на статическом хостинге. В production браузер по умолчанию запрашивает **`/api/stt` и другие `/api/*`** на текущем домене. Настройте reverse proxy для перенаправления на backend **либо** перед сборкой укажите `VITE_API_BASE_URL=https://api.example.com` и включите CORS на сервере. Ключи и токены LLM/STT/TTS должны оставаться на backend. Ссылку на публичный прототип можно получить только после реального деплоя.

### Обработка ошибок

- Ошибка HTTP выводится в чате/панели и не удаляет уже введённый вопрос.
- Недоступный микрофон и неподдерживаемый браузер — пояснения пользователю.
- Зависшие запросы ограничены тайм-аутом: чат 30 с, STT/TTS 45 с.
- Кнопка воспроизведения есть у каждого ответа, автоматическая озвучка выключена по умолчанию; можно включить значком динамика. После голосового запроса автоозвучка включается для конкретного ответа.
- Для разрешения микрофона нужен **localhost или HTTPS**.
- Не храните API-ключи STT/LLM/TTS во frontend: они должны оставаться на backend.

## Структура

```text
src/
  App.jsx                      # Состояния чата, сессии и событий; orchestration
  components/
    Sidebar.jsx                # Навигация и режим работы
    ChatPanel.jsx              # История, статусы, ввод, кнопка записи
    EventPanel.jsx             # Поиск/фильтры/периоды
    EventCard.jsx              # Задачи, встречи, напоминания
  hooks/
    useAudioRecorder.js        # MediaRecorder, MIME, таймер, cleanup
    useSpeechPlayback.js       # /tts, воспроизведение, освобождение URL
  services/
    api.js                     # Единственное место HTTP-интеграции
    demo.js                    # Только для локальной демонстрации
  utils/events.js             # CSV-конвертация, даты, нормализация, фильтры
  data/seedEvents.js          # Все 1000 исходных записей CSV
```

## Особенности CSV

Исходные колонки: **`id`, `date`, `time`, `text`**. В CSV 1000 строк с датами от 2024-01-07 до 2027-12-31. **Там нет типа записи, даты создания или статуса**, поэтому исходные строки показаны как «Событие» без выдуманных значений. Типы и статус `pending` появляются у новых записей, созданных локально или возвращённых backend. Данные в JSON сконвертированы без изменений значений CSV.

## Тесты и сборка

```bash
npm test
npm run build
npm run preview
```

Проверочные команды для демо-чата:

1. `Добавь встречу с командой завтра в 15:00`
2. `Что у меня завтра?`
3. `Поставь задачу подготовить отчёт в пятницу`
4. `Найди задачу про презентацию`
5. `Добавь встречу с Иваном завтра` → `в 11:00` (уточнение)

Примечание: при запросе **«какие задачи на завтра»** CSV-записи без типа не попадут в выборку именно задач. Они доступны через общий список и поиск. Для автоматической категоризации исторических записей потребуется отдельная логика backend.

## Спринты

- **S0:** готовый адаптивный интерфейс, каркас React + Vite.
- **S1:** MediaRecorder, индикация записи, multipart `/stt`, `/chat`, аудио `/tts`, текстовый ввод.
- **S2:** карточки типов, статус, периоды, фильтры, пустые/загрузочные/ошибочные состояния.
- **S3:** контекст в `session_id`, вопросы от ассистента, автоскролл, очистка истории, адаптивная мобильная навигация.
- **S4:** провести ручное тестирование на Chrome/Safari/мобильных браузерах **после развёртывания** и записать demo-видео. Эти действия нельзя считать выполненными автоматически.

## Что улучшать дальше

Общая авторизация и серверные диалоги, обработка конфликтов встреч, редактирование/удаление/отметка выполненной, пагинация и серверный поиск, ограничение длины озвучки, доступные команды клавиатуры, E2E-тесты на реальном backend. Для работающего публичного прототипа нужен отдельный HTTPS-деплой frontend и backend.
